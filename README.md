# Multi-Host Dendritic NixOS Configuration

This repository provides a clean, modular, multi-host NixOS Flake configuration adhering to modern NixOS standards (NixOS 26.05 / Unstable).

## 1. Architecture Overview

The configuration is structured as a dendritic tree using `flake-parts` and `nix-wrapper-modules`. The `flake.nix` file serves as a minimal entry point, delegating to various modular branches:

- `hosts/<hostname>/`: Contains hardware-specific definitions (`default.nix`, `hardware-configuration.nix`) for each machine (e.g., `host-alpha`, `host-beta`).
- `modules/core/`: Contains foundational, generic system modules (`boot.nix`, `disko.nix`, `locale.nix`, `desktop.nix`, etc.).
- `modules/programs/`: Contains self-contained, single-responsibility leaf modules for user and system applications using `nix-wrapper-modules`.

We avoid large monolithic arrays of `environment.systemPackages` or `home.packages`. Instead, every tool gets its own module.

## 2. Adding a New Package Wrapper

To add a new application, create a leaf module under `modules/programs/<app>.nix` using `nix-wrapper-modules`.

Example (`modules/programs/htop.nix`):

```nix
{ config, lib, pkgs, ... }:

let
  cfg = config.mySystem.programs.htop;
in {
  options.mySystem.programs.htop.enable = lib.mkEnableOption "htop";

  config = lib.mkIf cfg.enable {
    # Using nix-wrapper-modules concepts
    # In practice, you might use inputs.wrappers.nixosModules or similar
    # or define the wrapper in a central place.
    # We map this in our flake logic to generate wrapped derivations.
    environment.systemPackages = [
      # If using simple wrapper directly:
      # inputs.wrappers.lib.wrapPackage { ... }
      pkgs.htop
    ];
  };
}
```

*Note: You must define the inputs.wrappers in your flake.*

## 3. Adding a New Host

To onboard a new machine:

1. Create a directory `hosts/<new-host>/`.
2. Add a `hardware-configuration.nix` (often generated by `nixos-generate-config`).
3. Add a `default.nix` that imports core modules, specifies overrides, and sets `networking.hostName = "<new-host>";`.
4. Register the host in `flake.nix` under the `flake-parts` configuration.

## 4. Secrets Bootstrap (`sops-nix`)

We use `sops-nix` for secret management.

1. Generate an `age` key on the target machine or locally:
   ```bash
   nix-shell -p age --run "age-keygen -o keys.txt"
   mkdir -p /var/lib/sops-nix/
   cp keys.txt /var/lib/sops-nix/key.txt
   ```
2. Get the public key and put it in `.sops.yaml`.
3. Create a hashed user password:
   ```bash
   nix-shell -p mkpasswd --run "mkpasswd -m yescrypt"
   ```
4. Create and encrypt your secrets file:
   ```bash
   nix-shell -p sops --run "sops secrets/secrets.enc.yaml"
   ```
   Add the following to the file:
   ```yaml
   user-password: "YOUR-HASHED-PASSWORD"
   ```

## 5. Fresh Installation & Disko Partitioning

Boot into the NixOS Live ISO.

```bash
# Clone the repository
git clone https://github.com/your-user/your-repo.git /mnt/etc/nixos
cd /mnt/etc/nixos

# Run disko to partition and format the disk (Assuming /dev/nvme0n1)
nix run github:nix-community/disko -- --mode disko /mnt/etc/nixos/modules/core/disko.nix --arg device '"/dev/nvme0n1"'

# Install NixOS
nixos-install --flake .#host-alpha

# Reboot
reboot
```

## 6. TPM2 Enrollment

After installing and booting into the new system, enroll the LUKS partition to your TPM2 chip for automatic unlocking:

```bash
# Find your LUKS partition (e.g., /dev/nvme0n1p2)
lsblk

# Enroll TPM2 (replace with your partition)
sudo systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=0+2+7 /dev/nvme0n1p2
```
